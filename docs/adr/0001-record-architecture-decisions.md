## 文脈

このリポジトリはハーネス（`.claude/`）とループ（`.loop/`）でエージェントを自走させる。
ループは**文脈をリセットしながら回る**。次の周のモデルは前の周が何を考えたかを持っていない。

いま判断が漏れる先は3つあるが、どれも判断の記録にはならない。

| いまある場所 | 何が残るか | 足りないもの |
| --- | --- | --- |
| `.loop/done.md` の `メモ:` | 次の周への申し送り | 1〜2行。なぜそう決めたかと代替案が残らない |
| `.loop/backlog.md` の `blocked:` | 止まった理由 | 止まらなかった判断は残らない |
| `.claude/skills/` | 決まった**結論** | 結論だけで、そこに至った文脈が消える |

結果として、次の周は「なぜ Dynamo にしたのか」をコードから逆算できず、平気で覆す。
`code-reviewer` も根拠が無い以上その逆行を止められない。
**結論（skills）とは別に、判断の履歴を置く場所が要る。**

## 決定

設計判断を `docs/adr/` にMADR風のMarkdown 1ファイルとして残す。
ADRはループの成果物とし、`/work-next` の分解段階でオーケストレータ（opus）が要否を判定して
枝の上に書く。`code-reviewer` は「ADR相当の判断があるのにADRが無い」を Blocker として扱う。

## 結果

### よくなること

- 文脈がリセットされても、判断の**理由と代替案**がリポジトリに残る
- `code-reviewer` が「既存ADRに反する実装」を根拠つきで止められる。
  これまで根拠が無く止められなかった逆行が止まる
- 「どうやるか」は `skills/`、「何をするか」は `backlog.md`、「なぜそう決めたか」は `docs/adr/` と
  記録の役割が分かれる

### 悪くなること

- 1周あたりの手数が増える。設計判断を含む周は必ずADRを1件書く
- 起票基準が緩いと `code-reviewer` が誤爆し、差し戻し上限3回を無駄に溶かす。
  基準を `.claude/skills/adr/SKILL.md` に**狭く**定義して運用する責任が生まれる
- 索引（`docs/adr/README.md`）は手で維持するので、書き忘れると実体とずれる

## 検討した代替案

- **`.loop/done.md` の `メモ:` を厚くする** — `done.md` は追記のみの完了ログで、
  1周1エントリの粒度。判断は周をまたいで生き、supersede もされるので粒度が合わない。
  検索性も落ちる
- **`.claude/skills/` に理由を書き足す** — skillsは「いま従うべき結論」を短く保つのが仕事。
  覆された過去の判断まで抱えると、実装エージェントが読む規約が膨らんで読まれなくなる
- **何も導入せず現状のまま**（`done.md` の `メモ:` と `skills/` に任せる） — 判断が残らない状態が
  そのまま続く。ループが速くなるほど、理由の分からない設計がリポジトリに積まれる速度も上がる
- **ADRを置かず、コミットメッセージとPRに任せる** — このループは `push` も PR も作らない
  （`.loop/LOOP.md` 禁止事項）。外向きの記録に依存できない
- **`.loop/adr/` に置く** — `.loop/` はループの**運転状態**（何を取るか・何が終わったか）。
  ADRはアプリの設計に属し、ループを外しても価値が残る。混ぜると `.loop/` の役割が濁る
