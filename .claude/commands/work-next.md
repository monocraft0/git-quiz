---
description: バックログの先頭タスクを1件、完了条件を満たすまで実装する（ループ1周ぶん）
allowed-tools: Read, Write, Edit, Bash, Grep, Glob, Task
---

ループの**1周**を実行する。人に次の指示を聞かず、`.loop/backlog.md` から仕事を取る。

作業前に必ず `.loop/LOOP.md` を読み、そこの規約（完了条件・差し戻し上限・ブランチ運用・
モデル配分・禁止事項）に従う。`$ARGUMENTS` が与えられた場合は、そのタスク名に一致する行を
優先して取る。

このコマンドは**オーケストレータ**（opus）として回る。**分解・判断・統合が仕事**で、
実装のキーストロークは仕事ではない。詳細は `.loop/LOOP.md`「モデル配分」。

## 手順

1. **前提を確認** — ここが崩れていると後段でファイルを失う。

   ```bash
   git status --porcelain     # 空でなければ着手しない
   git rev-parse --abbrev-ref HEAD   # ← これが base ブランチ。以降 <base> と書く
   ```

   - 未コミットの変更があれば、**何もせず**「作業ツリーが汚れている」と報告して終了。
     手順12で `reset --hard` / `clean -fd` を使うため、巻き込んで消す危険がある。
   - `<base>` が `loop/` で始まっていたら、前の周から戻れていない。報告して終了。

2. **取る** — `.loop/backlog.md` の先頭の未完了 `- [ ]` を1件。
   - 未完了行が無ければ「バックログが空」と報告して**ここで終了**（何も作らない）。
   - `blocked:` が付いた行は飛ばす。人が解いていないので同じ壁に当たる。

3. **切る** — `git switch -c loop/<slug>`（`<slug>` はタスク名のkebab-case）。
   既に同名ブランチがあれば末尾に連番を足す。

4. **分解** — ここは**自分でやる**。ループで一番難しいのはこの手順。

   - タスクをスライスに割る。縦断機能なら backend → frontend の順に依存が流れる。
   - 各スライスについて **何を作るか / どのディレクトリに触るか / 完了の形** を決める。
   - タスクの `見て確かめること:` を、**どう出力させれば見られるか**に翻訳する
     （何を `.loop/artifacts/<slug>/` に出させるか）。手順10で使う。
   - **テストリストを作る**。`見て確かめること:` と完了条件を、**実行できるテスト**の一覧に
     翻訳する（正常系1本 → 境界 → 失敗系）。これは仕様の決定なので**自分でやる**。
     実装エージェントに決めさせると、実装しやすいものだけがテストになる。
     書式と粒度は `.claude/skills/tdd/SKILL.md`「テストリストの作り方」。
   - テストリストが作れないスライス（設定・配線・見た目のみ）は、その旨と理由を
     分解結果に明示する。タスク行に `tdd: n/a <理由>` があるかも確認する。
   - スキーマ変更の有無と `db:` の行き先（postgres | dynamo | none）を確定させる。
   - **ADRの要否を判定する**。基準は `.claude/skills/adr/SKILL.md`
     （後戻りが高い / 選択肢が複数あった判断だけ。命名や規約どおりの実装は対象外）。
     タスク行に `adr: required` があれば必ず書く。要否と**その理由**を分解結果に明示する。
   - 既存コードの形が分からないと分解できない場合だけ、自分で Read / Grep して確かめる。
   - **ここで実装コードは書かない**。書くのは次の手順で渡す指示文。

5. **委譲** — 実装は**サブエージェントに渡す**。原則、自分で Write / Edit しない。

   | スライス | エージェント | model |
   | --- | --- | --- |
   | バックエンド（controller / service / repository / migration / JUnit） | `backend-dev` | タスクの `model:`（既定 sonnet） |
   | フロントエンド（component / hook / types / Vitest） | `frontend-dev` | タスクの `model:`（既定 sonnet） |
   | 機械的な作業（TODOコメント削除、リネーム、定型のテスト追加、1ファイルの小修正） | 上の担当と同じ | `model: haiku` |

   - タスクに `model:` があればそれを `Agent` の `model` に渡す。無ければ既定。
     選び方の基準は `.loop/LOOP.md`「タスクごとにモデルを決める」。
   - **差し戻し2回目に入るときは `model:` を1段上げる**（haiku → sonnet → opus）。
     1回目は同じモデルで再試行してよい（指示の不足であることが多い）。
     上げた事実と結果は `done.md` に残す。

   - 依存のあるスライスは**直列**に呼ぶ。backend が返した**実際のDTOの形**を
     frontend への指示に埋め込む（型ズレは verifier の常連Blocker）。
     依存が無ければ1回の応答でまとめて呼ぶ。
   - 渡す指示に必ず入れる: スライスの範囲 / **触ってはいけないディレクトリ** /
     読むべき SKILL.md（`tdd` は必ず含める）/ **そのスライスのテストリスト** /
     完了条件（リストの全件が赤→緑を通り、担当範囲のテストが緑）/
     **赤コミットを残すこと**（`test: <対象> — red (<落ちたテスト名>)`）。
   - **実装は赤から始めさせる**。テストリストの1件ずつ、
     「テストを書く → 走らせて赤を見る → テストだけコミット → 最小限の実装で緑 → コミット」。
     コンパイルエラーは赤に数えない（シグネチャのスタブを先に置かせる）。
     既存テストを変更・削除するスライスでは、**そのぶんだけ**ミューテーション自己検証を
     指示する（`.loop/LOOP.md`「ミューテーション自己検証は『残り』に絞る」）。
   - **サブエージェントは文脈を持たない**。タスク名だけ投げない。
     既存コードのシグネチャや実際のレスポンス形は、指示文に**そのまま埋める**。
   - **横道に逸れない**。気づいた別の問題は `.loop/backlog.md` に**追記するだけ**。
   - `make test` が DB を起動しない制約（`@SpringBootTest` / `@DataJpaTest` 不可）は
     バックエンドの指示に**毎回**書く。書き忘れると確実に blocked になる。

6. **ADRを書く**（手順4で「要」と判定した場合、**または手順9でADRのBlockerを受けた場合**）
   — **自分で書く。委譲しない。**

   判断はオーケストレータの仕事で、`backend-dev` / `frontend-dev` は
   「判断が要る問題は自分で決めずに報告に上げる」側。ここを渡すとモデル配分が壊れる。

   - `.claude/skills/adr/SKILL.md` の書式・採番に従い `docs/adr/NNNN-<kebab>.md` を作る。
     採番は **Glob（`docs/adr/[0-9]*.md`）** で取る（`ls` は許可リストに無く、承認待ちで止まる）。
     `status: accepted`、`branch: loop/<slug>` を入れる。
   - 既存ADRを覆す場合は、旧ADRの frontmatter だけを `superseded` にする（本文は書き換えない）。
   - `docs/adr/README.md` の索引に1行足す。
   - **ADRは枝の上に置く**（`.loop/` と違って base に出さない）。verifier のレビュー対象に
     入れるため。blocked で枝ごと捨てられたら消えてよい ＝ 採用されなかった判断は決定ではない。

7. **機械ゲート** — `make test && make build`。
   - **緑を信じる前に `cd <repo>/backend && ./gradlew test --rerun-tasks` で再実行する。**
     Gradle は UP-TO-DATE で実行をスキップし、古い結果を緑と誤認させる（実際に事故が起きている）。
   - **赤の記録を確かめる**。緑は「テストが機能している」証拠ではない。

     ```bash
     git log --oneline --stat <base>..HEAD   # test: ... — red が実装コミットの前にあるか
     ./.claude/hooks/check-conventions.sh <base>   # 順序を機械的に見る
     ```

     報告に落ちたテスト名が無い、または履歴に先行する test-only コミットが無ければ、
     **verifier に回さずに差し戻す**。既存テストを変更した部分については、
     ミューテーション自己検証の結果（何を壊し、どのテストが落ちたか）を同様に確かめる。
     `tdd: n/a` の周は、その理由が分解結果と一致しているかだけ見る。
   - スキーマを触った周は、**実機で確認する**。`make restart`（`make backend` は health が
     応答する限り再起動せず古いコードのまま動く）してから API を叩き、Flyway の適用と
     `ddl-auto: validate` の通過を確かめる。**これは機械ゲートでは検出できない**。
   - 赤なら**原因を特定するのは自分**。そのうえで、
     - 原因が1〜2行で言い切れる → 自分で直す（往復のほうが高い）
     - それ以外 → 担当エージェントに**何がどう落ちたか**を添えて差し戻す
   - 再実行は**最大3回**。超えたら手順12へ。

8. **verifier を呼ぶ前に、実装をブランチへコミットする。**

   ```bash
   git status --porcelain    # 空なら実装エージェントが既にコミット済み。この手順は飛ばす
   git add -A && git commit -m "wip: <タスク名>"   # 手順11で --amend か squash する
   ```

   **赤コミットは畳まない。** ここで畳んでよいのはこの wip だけで、
   実装エージェントが残した `test: ... — red` と対の実装コミットはそのまま枝に残す。
   verifier はその時点をチェックアウトして赤を再現する（`.loop/LOOP.md`）。

   レビューは長い。その間にエージェントが API エラーやセッション上限で落ちると、
   未コミットの実装は宙に浮く（実際に2回起きた）。コミットしておけば、
   最悪でもブランチから再開できる。**untracked のファイルも忘れず含める**
   （`git diff` に出ないため、verifier への連絡でも見落としやすい。新設した
   `docs/adr/*.md` もここに含まれる）。

9. **verifier** — `code-reviewer` エージェントを起動し、判定を受け取る。

   起動する**前に**、機械的に確認できる点は自分で潰しておく
   （この周で新しく使うコマンドが `.claude/settings.json` の許可リストにあるか /
   手順書やスキルを編集した場合、内部の相互参照〈番号・パス〉が一致しているか /
   追加した相対リンクが実在ファイルに解決するか）。ここを先に潰すと、`code-reviewer` が
   拾う指摘はモデルでないと判定できないものに絞られ、差し戻しの往復
   （＝フルコンテキストの読み直し）が減る。

   - 起動時に渡す: 変更ファイル一覧（**untracked は `git diff` に出ないので明記**）/
     **赤コミットのハッシュと落ちたテスト名**（verifier がその時点を再現する）/
     実装エージェントの自己検証の結果 / 自分が実機で確認した内容 /
     **スコープ外として自分が判断済みの項目とその理由**（判断を丸投げしない。
     ただし迷うものは「判断を仰ぐ」と書いて委ねる）。
   - **自分がタスクの完了条件を上書きしたり設計を指定した場合は、それを明示して
     「これは私の判断なので評価してほしい」と渡す。** オーケストレータの指示が
     差し戻しの原因になった実例が複数ある（広い例外型を 4xx に倒す指示が
     サーバ側のバグを隠す設計だった件、テストの重複を整理させた結果、
     唯一の検出アンカーを消してしまった件）。明示した周では verifier が
     実際に誤りを指摘して覆した。
   - **注入試験の結果を都合よく読まない**。「赤になった」だけでなく**なぜ赤になったか**を見る。
     モックのスタブ不足で落ちただけを「検出できている」と読み違えた実例がある。
   - verifier はミューテーション試験を**リポジトリの複製の上で**行う。判定を受け取ったら、
     `git status --porcelain` で作業ツリーが渡す前と一致しているか**自分でも確かめる**。
     試験の書き込みが残ると、次の実装エージェントがそれを正しい実装だと信じる。
   - `FAIL` なら Blocker を担当エージェントに差し戻し、手順7に戻る。**最大3回**。
     超えたら手順12へ。差し戻しには Blocker の**原文**を渡す（要約すると落ちる）。
   - ただし **ADRに関する Blocker（欠落 / 既存ADRへの無断の逆行）は差し戻さない**。
     自分で手順6を実行してから手順7へ。実装後に判断が判明する周は普通にあり、
     ここを実装エージェントに渡したら判断を委譲したのと同じ（`.loop/LOOP.md`「モデル配分」）。
     **この往復も上の3回に数える**（数えないと同じ指摘で無限に回りうる）。
   - ADRと実装のBlockerが**混在**したら、**同じ往復で両方**片づける。
     実装ぶんを担当エージェントに差し戻し、その戻りを待つあいだに自分がADRを書く。
     順番に回すと1件のFAILで上限を2つ消費する。
   - **2回目以降のレビューは差分限定にする**。前回のレビュー時点からの差分
     （`git diff <前回レビュー時のコミット>`）と、前回の Blocker への対応だけを渡し、
     「変わっていない箇所は再レビュー不要」と明示する。実測では再レビューが
     既レビュー済みファイルまで毎回フルで走り、2回目以降だけで 444,008 トークンを
     使っていた。
   - タスクに `review:` があればそれを `Agent` の `model` に渡す。
   - `PASS` なら手順10へ。
   - 自分でPASSと判断しない。**必ずエージェントを呼ぶ**。

10. **出力ゲート** — 成果物を**実際に見る**。ここは自分でやる（委譲しない）。

    - 実装エージェントに `.loop/artifacts/<slug>/` へ成果物を出させる
      （レンダリング結果・スクリーンショット・実リクエスト/レスポンスのログなど）。
      出しにくいものは自分でスクリプトを書いて出す。
    - **開いて見る**。画像なら画像として（`Read` で読める形に変換する）、
      画面なら `make start` して操作する、APIなら実際に叩く。
    - タスクの `見て確かめること:` を満たさなければ**実装に差し戻す**（機械ゲートと同じ上限）。
    - テストとレビューはどちらも出力を見ていない。**ここを飛ばすと、
      全ゲート緑のまま用をなさないものが `done.md` に積まれる**（実例は `.loop/LOOP.md`）。

11. **記録**（PASS時） — この順で行う。`.loop/` の更新は枝ではなく `<base>` 上で行う。

    ```bash
    git add -A && git commit -m "<タスク名>: <何をしたか>"   # 畳んでよいのは手順8の wip だけ
    git switch <base>
    git merge --no-ff loop/<slug> -m "loop: <タスク名>"
    ```

    - **赤コミットを squash しない**。`test: ... — red` と対の実装コミットは枝に残したまま
      `--no-ff` でマージする。畳むと、あとから「テストが先だったか」を確かめる手段が消える。
    - マージ後、`<base>` 上で `.loop/backlog.md` から該当行を削除。
    - `.loop/done.md` に `LOOP.md` の書式で追記。日付は `date +%F` で取る。
      ADRを起票した周は `- adr:` 行にそのパスを入れる。
      `- 赤:` 行に赤コミットのハッシュと落ちたテスト名（`tdd: n/a` の周は理由）を入れる。
    - `.loop/` の更新を `git commit -m "loop: <タスク名> を done へ"` でコミット。
    - **枝は消さない**（1周ぶんの差分を後から読めるように残す）。
    - **push も PR も作らない**。

12. **blocked**（上限超過時） — **作りかけのコードを捨てて**ループを止める。
    この順で行う（順序を守らないと `blocked:` の記録ごと消える）。

    ```bash
    git reset --hard HEAD          # 未コミットの変更を破棄
    git clean -fd                  # 新規作成したファイルも破棄（-x は付けない＝.env等は残す）
    git switch <base>
    git branch -D loop/<slug>      # 手順8の wip コミットごと捨てる
    ```

    - `<base>` 上で `.loop/backlog.md` の該当タスクに
      `blocked: <どのゲートで何が通らなかったか。エラーの要点>` を追記してコミット。
    - どのゲートで何回落ちたか、何を試したかを人に報告する。
    - 残すのはコードではなく**理由**。作りかけを残しても次の周は文脈を持たない。

## 報告

1周の終わりに、次を簡潔に報告する。

- 取ったタスクと結果（完了 / blocked / バックログ空 / 前提エラー）
- ブランチ名とコミットハッシュ（完了時）
- **分解したスライスと、どのエージェント・どのモデルに渡したか**
- **赤の記録**（赤コミットのハッシュと、そこで落ちたテスト名）。
  テストを先に書かなかったスライスがあれば、その範囲と理由を1行
- 各ゲートの結果（機械ゲート何回目で緑 / code-reviewer の判定 / **出力ゲートで何を見て何を確認したか**）
- **起票したADRのパス**。起票しなかった場合は「ADR不要と判断した理由」を1行
- backlog に追記した新しい気づき（あれば）
