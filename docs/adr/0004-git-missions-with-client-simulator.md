## 文脈

初学者向けに「git操作を学ぶ」クイズにしたい。4択（ADR 0003）では、コマンド名を
覚えているかは問えても、**コマンドを打つと何が起きるか**（ステージに載る、コミットが
増える、ブランチが動く、HEADが移る）が身に付かない。そこで、ユーザーがコマンドを入力し、
その結果をコミットグラフや作業ディレクトリ／ステージングエリアの図として**その場で
動かして見せる**形に作り替える。

これには2つの判断が要る。

1. gitの挙動をどこで再現するか（ブラウザ / サーバー / 本物のgit）。
2. 「正解」をどう定義し、どこで判定するか。4択と違い、正しいコマンド列は1通りではない
   （`git switch -c` と `git branch` + `git switch` は同じ結果になる）。

ADR 0003 の「正解をクライアントに事前に渡さない」「判定はサーバー側で行う」という
方針は残したい。

## 決定

- gitの挙動は **フロントエンドの TypeScript 製シミュレータ**（`frontend/src/features/gitsim`）で
  再現する。初学者向けのサブセット（add / commit / branch / switch / checkout / merge /
  reset / restore / status / log）に限り、コンフリクト・リモートは扱わない。
- 問題は「ミッション」とし、`GET /api/missions` は 初期状態を作るコマンド列と、
  目標の**説明文だけ**を返す。目標の判定条件・模範解答・解説は返さない。
- 判定は `POST /api/missions/{id}/judge` にリポジトリ状態のスナップショット
  （HEAD・各ブランチから到達できるコミット・ステージ／変更／未追跡ファイル）を送り、
  サーバーがDBに持つ目標条件と照合する。**コマンド列ではなく結果の状態で判定する**。
- 旧4択の `quiz_questions` と `/api/quiz/**` は削除する。ADR 0003 はこれで置き換える。

## 結果

### よくなること

- 1コマンドごとに図が即座に動く（ネットワーク往復なし）。
- 状態で判定するので、別解のコマンド列でも正解になる。
- 判定条件・模範解答・解説はサーバーにだけあり、判定前のレスポンスに現れない（0003の方針を維持）。

### 悪くなること

- gitの挙動をフロントに自前実装するので、本物のgitとの差が生まれうる（コンフリクト・
  リモート・detached HEADでのコミットなどは非対応）。対応範囲を広げるたびにシミュレータの
  テストが増える。
- サーバーはクライアントが送る状態を信用する。改ざんすれば「正解」にできるが、
  学習用クイズでありスコアに価値が無いため受け入れる。
- コミットIDはシミュレータが決定的に採番する。初期状態コマンドを変えると
  IDが変わるため、判定条件にコミットIDを書いてはいけない（ブランチ名・件数・包含で書く）。

## 検討した代替案

- **サーバーでシミュレータを動かし、コマンド1行ごとにAPIを叩く** — 判定と挙動が1箇所に
  閉じるが、1キー入力ごとに往復が発生し、図のアニメーションが遅延する。Kotlin側に
  状態保持（セッション）も要るため不採用。
- **本物のgitをサーバーのサンドボックスで実行する** — 挙動は正確だが、任意コマンド実行の
  隔離が必要で、テンプレートの範囲を超えるため不採用。
- **目標条件もクライアントに渡し、フロントだけで判定する** — 実装は最小だが、
  模範解答と解説が判定前に見えてしまい、0003の方針に反するため不採用。
- **コマンド列を模範解答と文字列比較する** — 別解を不正解にしてしまうため不採用。
