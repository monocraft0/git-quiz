---
description: テスト失敗とTODOコメントを走査してバックログに積む（仕事の自動発見）
argument-hint: [--test | --todo]
allowed-tools: Read, Edit, Bash, Grep, Glob
---

既存コードの不備を走査し、`.loop/backlog.md` にタスクとして積む。**実装はしない**。

作業前に `.loop/LOOP.md` の「仕事の源泉」と backlog の書式を読む。
`$ARGUMENTS` に `--test` / `--todo` があれば、その走査だけ行う（既定は両方）。

拾えるのは**既にある不備**だけ。新機能は人が `backlog.md` に書く。ここを混同しない。

## 手順

1. **既知のものを集める** — `.loop/backlog.md` と `.loop/done.md` を読み、
   記録済みの `source:` をすべて控える。この後の重複判定に使う。

2. **テスト失敗を走査**（`--todo` 単独指定時は飛ばす）

   `make test` は最初の失敗で止まるので、**個別に走らせて両方の結果を得る**。

   ```bash
   cd backend && ./gradlew test --continue; cd ../frontend && npm test
   ```

   - 失敗した**テスト単位**でタスク化する。
   - ただし1つの原因で複数テストが落ちているなら、**まとめて1タスク**にする
     （粒度が細かすぎると同じ修正を何周も繰り返す）。
   - `source: test <テスト識別子>` を付ける。例: `source: test HealthControllerTest.returns200`
   - **失敗しているテストは、それ自体が赤**。このタスクを取る周は新しく赤を作る必要が無く、
     そのテスト名と失敗内容を赤の記録として使う（`.claude/skills/tdd/SKILL.md`）。
     タスク行に `source:` があるので、`tdd:` は書かない。

3. **TODO / FIXME を走査**（`--test` 単独指定時は飛ばす）

   ```bash
   grep -rn -E 'TODO|FIXME' backend/src frontend/src
   ```

   - 1件 = 1タスク。本文が具体的でなければ、周辺コードを読んで
     「何をすれば消せるか」がわかる粒度のタスク名に書き直す。
   - `source: todo <path> "<TODO本文>"` を付ける。**行番号は入れない**（ずれるため）。
   - **完了条件に「該当のTODOコメント自体を削除する」を必ず含める**。
     消し忘れると次の `/find-work` が同じ仕事を再び積む。
   - TODOが**振る舞いの欠落**を指しているなら、その周は赤から始まる。
     コメント削除や整形だけで振る舞いが変わらないものは `tdd: n/a <理由>` を付ける。

4. **重複を除いて積む** — 次のいずれかに当たるものは**積まない**。

   - `backlog.md` に同じ `source:` の行が既にある
   - `done.md` に同じ `source:` の記録がある
   - `blocked:` 付きで backlog に残っている（人がまだ原因を解いていない）

5. **追記** — `.loop/backlog.md` の**末尾**に足す。既存の並び順は変えない。
   人が書いたタスクを追い越さないため、先頭には入れない。

## 報告

- 走査した対象（テスト / TODO）と検出件数
- 実際に積んだ件数と、重複で捨てた件数
- 積んだタスクの一覧（1行ずつ）

**バックログが消化速度を超えて膨らんでいないか**は人が見る。
毎回大量に積まれるなら、それは仕事ではなく規約かスキル側の不足の兆候。
